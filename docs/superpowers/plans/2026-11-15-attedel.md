# AttedDEL implementation plan

> Execute inline with superpowers:executing-plans. Preserve prior local changes.

**Goal:** Complete the laptop webcam attendance workflow specified in docs/REQUEST.md.
**Architecture:** Extend existing services and pages; use the database as biometric source of truth and one canonical recognition pipeline. Keep frame loops sequential with cancellation.
**Tech Stack:** FastAPI, async SQLAlchemy, SQLite/PostgreSQL, InsightFace, React/TypeScript/Vite.
**Spec:** docs/REQUEST.md

## Global constraints
No webcam access, fake embeddings, secrets, destructive resets or architecture replacement. UNIQUE(session_id, student_id) remains. Each phase ends with full pytest and frontend build; failures are diagnosed before proceeding.

## Review focus
Bootstrap races; revoked/disabled users; biometric persistence and duplicate identities; mirrored coordinates and stopped cameras; cross-session temporal state and closed-session writes.
