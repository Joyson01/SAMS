# Laptop webcam acceptance checklist

Automated checks used real image files and Chromium's file-backed fake camera. They do **not** prove physical webcam permission/device behavior, actual head-pose guidance, or recognition of you. Default enrollment requires seven poses; automated smoke explicitly uses only FRONT in an isolated test environment.

1. Install Python 3.11–3.13 (or Python plus uv) and Node.js 20+ with npm. From this folder run `./start.sh` (Windows: `start.bat`). Wait for the URLs and model status. Open the printed localhost frontend URL.
2. On an empty development database, sign in as `admin` / `Admin@12345`. In Users, select this account and set a new password with at least 8 characters, a letter and a digit. Password reset revokes sessions; sign in again. Alternatively run `python -m scripts.create_admin` in the application venv before first startup, or visit `/setup` while no admin exists. Outside development setup requires BOOTSTRAP_TOKEN.
3. Sign out. Open Register, create a student account, then check that only My Attendance is available. Try a duplicate email and a password without a digit: expect an explanatory error. Sign out and return as admin.
4. In Courses & Rooms (More Tools), create a class and subject. Use Lab batches & class subjects to create a batch and map the subject. Save the same mapping twice: neither save should fail. In Timetable use Manage timetable slots to add, edit and delete a slot.
5. In Students, create yourself and a second student in the same class. Enter name, unique roll number, student code, department and email. Select the class and batch. In Users, link the student account using its roll number and student code. The second student will test automatic absence.
6. Open face enrollment from your student row. Start camera and allow permission. Expect a mirrored preview, face guide, device selector, and feedback. Move out of view: no face. Include another person: only one face. Cover the light: quality warning. Deny permission or disconnect the camera: an actionable message, not a blank page.
7. Follow all configured pose steps: FRONT, LEFT_15, RIGHT_15, TILT_UP, TILT_DOWN, ROLL_RIGHT and BACKUP_FRONT by default. Hold a valid pose for about a second for auto-capture, or use Capture. Retake a saved step: count should not increase. Refresh and return: progress should persist. Attempt to enroll the same face for the second student: expect a conflict, not a second identity.
8. Open `/recognition-test`. Start camera. Expect a box following your face, name and cosine similarity, VERIFIED/CANDIDATE/UNKNOWN coloring, face count, frame rate, latency, gallery count and thresholds. Resize the window; the box must stay aligned with the mirrored face. Test an uploaded photo too. A different unenrolled person should be UNKNOWN; false matches must be investigated before trusting attendance.
9. Open Live Attendance. Create a session for your class/subject (or select a scheduled one), Start session, then Start camera. In good lighting expect VERIFYING then PRESENT in roughly 2–3 seconds. A late scheduled arrival may be LATE. Stay in frame: only one record. Leave and return: camera visibility changes but no duplicate record.
10. Hide the tab: requests pause. Return: processing resumes. Stop camera or navigate away: browser camera indicator must turn off. Switch sessions: the new session must require fresh verification. Check mobile/RTSP separately using the advanced source button and proper HTTPS for LAN phones.
11. Use roster Edit to make a manual override with remarks. Finish Attendance and accept the confirmation. Expect counts and the second student ABSENT. Camera must stop; API recognition on this session must return 400.
12. Open Photo Attendance with a new active session. Upload a group photo. Preview should not mark attendance. Review VERIFIED/NEEDS_REVIEW/UNKNOWN faces and confirm choices. Duplicate identity selections should be disallowed; a second confirmation should not duplicate records. MANUAL_PRESENT and EXCUSED must remain protected.
13. Open Reports, filter your class/session and export CSV. Compare records and totals with the final roster. Sign in as the linked student and check My Attendance.
14. Restart the app. Confirm saved students, enrollment, records and gallery availability. Check System Health: connected database, loaded AI engine, gallery size and CPU/CUDA provider.

Still to run on real hardware: seven-pose capture and directional hints, actual camera contention/permissions, changing camera devices mid-stream, Windows/macOS launch, phone HTTPS and RTSP. Pose angles are approximate five-landmark estimates. Recognition similarity is not a probability, and passive liveness is not strong anti-spoofing.
